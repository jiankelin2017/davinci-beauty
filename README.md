> 上一版：**1.1.2.1（2026-11-07）** —— **修「白块」的第一次尝试被真机证伪，本版改为先取像素证据**。1.1.2.0 把 `g_maskShape` 默认从 0（矩形）改成 4（脖子逐行跟随肤色），想消掉「脖子上一块跟着人走的白色长方形」。零改动实验已把根因切得很干净：`BEAUTY_NECK_LEN=0` 白块消失（是脖子带）、磨皮拉 0 白块仍在（与磨皮无关）、关掉效果就正常（是插件不是宿主），于是锁定只对掩码内像素生效的 `toneColor`（美白 64 / 红润 30）。**但 4 档的结果是反的**：真机 36 条 `掩码诊断` 显示脖占比 **2.22% → 3.33%（+50%）**，脸几乎不动（5.20 → 5.18），观感从「长方形」变成「更明显的方形」。根因是 `beauty_core.cpp:911` 的 `kNeckSkinMaxHalf = 0.70f` 比旧矩形 `kNeckHalfW = 0.45f` **宽 1.56 倍**，而「连续 3 个非肤色才停」的探测在整行都判成肤色时会直接顶到上限、**边界退回直线** —— 4 档在浅色/肉色衣物上等价于「一个更宽的矩形」。本版不再推理：新增环境变量 `BEAUTY_DUMP_OUT=<目录>`，把前 6 个「检出脸且有掩码」的帧落盘成 `src`/`dst`/`mask` 三张 PPM/PGM（零依赖、行序按 `imgBottomUp_` 翻正、默认完全不执行），配 `04_验收工具/dump_analyze.py` 直接读出「变化区颜色 / 掩码直方图 / 提亮幅度 / 形状填充率」，一次分清「真皮肤被提亮」（→ 加长下缘羽化）还是「衣物被误判」（→ 脖子不吃色调）。**零影响是量出来的**：强制 `BEAUTY_MASK_SHAPE=0` 时基线 **18/18 PASS**，默认 4 档 0/18 且与 1.1.2.0 完全一致。产物 334,848 B，md5 `5b075b2737220bfa07f5e5e1b03c9fcb`。**`mask_shape` 建议回退到 0，待三张图定性后一并定版。**

> 现在带适配器型号与厂商 ID，出问题时先看那一行。**这一行的有效性由 1.0.10.0 保证**：
> 1.0.9.0 里它其实从未打印过，详见 `PROGRESS.md` 1.0.10.0 节。

> **1.0.8.0 更正了 1.0.7.0 的一个错误结论**：此前记录的「CPU 比 GPU 快 2~3 倍」
