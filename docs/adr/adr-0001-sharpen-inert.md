## 一句话结论

**锐化确实没用，但是两个独立原因叠加，而且第二个是我在 1.51 里引入的回归。**

| # | 原因 | 归属 | 严重程度 |
|---|---|---|---|
| A | 磨皮 > 0 时，SDK 的锐化对输出贡献**恒为 0** | SDK 自身行为，1.4 就这样 | 用户实际命中这个 |
| B | 1.51 的语义掩码把锐化撤掉 **93%** | **1.51 回归** | 磨皮=0 时才暴露 |

## 原因 A：磨皮 > 0 时锐化完全失效（字节级确证）

`python probe_sharpen.py --exact`，整帧 252160 像素逐字节比：

| 磨皮 | sharpen=0 vs sharpen=100 的不同像素数 | |
|---|---|---|
| 0 | 15912 / 206120 | 有差异（有效） |
| 20 | **0 / 252160** | 完全一致 |
| 50 | **0 / 252160** | 完全一致 |
| 100 | **0 / 252160** | 完全一致 |

语义区域开 / 关两种模式结果相同 → **与 1.51 无关，是 SDK 自身行为**。

**这意味着插件默认值就是坑**：`kParams[].dflt` 里磨皮默认 20。用户拖上效果、
只调锐化，磨皮还是 20 → 锐化必然毫无变化。代码注释里其实早就写了这条
（`ofx_plugin.cpp:143` 的工具提示），但没人在 default 上防住。

---

## 原因 B：1.51 的语义掩码把锐化压死了（新回归）

FACE  ROI 平均改动量（delta）：

| 用例 | 区域 ON（1.51） | 区域 OFF（1.4） | 存活率 |
|---|---|---|---|
| sharpen_25 | 0.12 | 1.89 | 6% |
| sharpen_50 | 0.27 | 3.83 | 7% |
| sharpen_100 | 0.55 | 7.70 | **7%** |
| clarity_100 | 1.48 | 7.51 | 20% |
| red_level_100 | 0.56 | 3.38 | 17% |
| blur_100 | 0.53 | 3.36 | 16%（**这是 Phase 2 想要的结果**） |

### 根因

`nama_engine.cpp` 的 `applyRegionEffects()` 做的是：

```cpp
const int d = (int)row[c] - (int)srow[c];      // SDK 输出 - 输入
row[c] = srow[c] + ((d * m256) >> 8);          // 按语义掩码等比例撤回
```

它把 **SDK 的全部输出改动**都按皮肤掩码撤回。但八项效果里只有**磨皮**需要
被限制在皮肤内（Phase 2 的成果：非皮肤区被磨 27.5–47.1% → 0.00%）；
锐化 / 清晰 / 红润 / 五官立体 / 亮眼 这些**本来就应该作用在人脸上**，
其中锐化主要增强的是眼睛、眉毛、嘴唇、发丝这些**高频细节**——
恰好全是语义皮肤掩码排除在外的地方。所以锐化被撤得最狠（存活 7%），
清晰这类低频效果还有 20%。

### 影响面

不只是锐化。清晰（clarity）从 87.4% 像素改动掉到 15.2%，红润从 77.3% 掉到 14.7%。
用户会觉得"1.51 的效果变弱了"。

---

## 好消息：清晰（clarity）是个能用的替代品

| 用例 | 区域 ON | 区域 OFF |
|---|---|---|
| clarity_100 单独 | 15.2% 改动 | 87.4% 改动 |
| clarity_100 + 磨皮 20 | 14.8% 改动 | 82.6% 改动 |
| clarity_100 + 磨皮 100 | 14.8% 改动 | 82.1% 改动 |

**清晰不受磨皮影响，能和磨皮共存。** 用户想要"锐利一点"的观感，现在就该用「清晰」。

---

## 修复方案（待用户决定）

### 方案 1：掩码只门控磨皮，不动其他效果（推荐，最正确）

思路：SDK 输出里把「磨皮的贡献」和「其他效果的贡献」分开，只掩码前者。

实现（二选一）：

- **1a 双次渲染**：磨皮和其他效果同时非零时，多渲一次「只开磨皮」的 SDK，
  然后 `out = pass_full - (pass_bluronly - src) * (1 - m)`。
  最准确，代价是一次额外 SDK 渲染（约 +5~10 ms/帧，只在该组合下发生）。
- **1b 频率分解**：把 `d = sdk_out - src` 拆成低频（磨皮）和高频（锐化/清晰细节），
  只掩码低频部分。代价是一次盒式模糊（约 +1~2 ms/帧），近似但便宜。

### 方案 2：锐化滑块改由 CPU 侧自己实现（USM）

SDK 的锐化既然和磨皮互斥，就在 CPU 侧写一个非锐化掩码，
磨皮之后跑，参数独立。约 20 行代码，代价约 +1~2 ms/帧，
好处是彻底自主可控、和磨皮共存、强度可标定。

### 方案 3：只修默认值和提示（零风险，最小改动）

- 把「锐化」工具提示改成："磨皮大于 0 时本项完全无效（SDK 行为）；
  需要锐利感请用「清晰」。"
- 可选：磨皮默认值从 20 改成 0，让用户先看到干净画面再自己加效果。
