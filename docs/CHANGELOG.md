## 当前版本 1.3.6.0（2026-11-08）— 美白门控的数据竞争

**一句话**：`toneColor()` 的 Sobel 边缘门控读的是**正被并行写入的 `dst`**，导致输出在 1% 量级上随机漂移；改成「先算边缘、再并行写回」。画面随之改变（0.2% 像素、最多 3 级），基线已重标。

| 事实 | 数据 |
|---|---|
| 现象 | 「逐字节回归」偶发 17/18，复跑又 18/18；失配用例不固定 |
| 机制 | 写回循环里读 `dst` 的上下左右邻域做 Sobel，而同一循环正按行并行写 `dst` |
| 证据 1：异常行落在块边界 | `blur62_wh100` 跑 2100 次，33 次异常（1.57%），异常行全部是 `261 + 35k` 及其 `y±1`（35 = 行块高） |
| 证据 2：归因到美白段 | 强制 CPU 各 300 次：只磨皮 `0/300`、加美白 `6/300`、加美白+清晰 `4/300` |
| 证据 3：与 GPU、推理线程数无关 | 强制 CPU 与强制 GPU 都抖；`BEAUTY_INFER_THREADS=1/2/4` 异常率同为 0.5% |
| 修复后 | `blur62_wh100`、`cl50` 各跑 1200 次，**单一 md5、0 次异常** |
| 画面变化 | `blur62_wh100`：1458 像素（0.22%）差 ≤3 级；`blur62_wh30`：192 像素差 1 级；`cl50`：700 像素差 1 级。差异全部落在脸部 ROI 内 |

**为什么画面会变**（不止是竞争那几行）：旧代码在同一行块内，处理第 y 行时 `y-1` 已被本线程写过、`y+1` 还没写，所以门控算的是「上邻域已美白、下邻域未美白」的混合值。改成统一读进入函数时的状态（即美白前），门控输入就与磨皮侧 `sobelEdge(src,…)` 对齐了——这才是原本的意图。

**没修的地方**：`clarityRgb()` 同样并行写 `dst`，但它只读自己那一像素，不构成竞争（已逐处核对）。

产物：`DaVinciBeauty_Setup_v1.3.6.0.exe`（4,856,294 字节，md5 `50436e91…`），装机 DLL md5 `c89e2daa…`。**同版随后因标识符改名重出**（见本节末），现为 4,857,026 字节、md5 `d3ab6f1d…`、DLL `8736d185…`。

验证：编译 0 error 0 warning、连编两次 md5 恒为 `c89e2daa…`；`baseline.py update` 一次通过（**不再需要** `BEAUTY_INFER_THREADS=1` 这个临时绕法）；`check` 连跑两次 18/18；`acceptance.py` 全量 PASS 28。

## 编号跳号与工作标签（不是「缺条目」）

**结论分三类，不要混为一谈**：

| 编号 | 定性 | 依据 |
|---|---|---|
| `1.3.0.0` | **确实没有这个号** | 无 commit、无安装包、装机目录也无 `.bak-1.3.0.0` |
| `1.2.6.0` | **有过这个构建**，但没进 git、没出包 | 装机备份 `DaVinciBeauty.ofx.bak-1.2.6.0` 内嵌字符串 `1.2.6.0`（其它备份的版本串都与自己的文件名一致） |
| `1.3.2` / `1.3.3` / `1.2.4.0` | **装机备份名 ≠ 内嵌版本**，是工作标签 | 三个备份 DLL 内嵌的分别是 `1.3.1.0` / `1.3.1.0` / `1.2.3.0` |

上一版本节写的是「`1.2.6.0` 与 `1.3.0.0` 从未成为版本号」——**对 `1.2.6.0` 是错的**。当时的证据只覆盖仓库（commit、产物目录、仓库内字节搜索），漏了 `C:\Program Files\Common Files\OFX` 下的装机备份。核对装机 DLL 后更正。

核查依据四条，互相独立：

**证据 2：安装包产物**（`05_安装包/build/`）
现存 13 个 exe，覆盖 `1.0.7.0`–`1.1.1.4` 与 `1.3.4.0`（含 sandbox）–`1.3.6.0`。**整条 `1.2.x` 与 `1.3.1.0` 都没有出过包**——那一串是同一天内部的连续迭代，第一次定版出包是 1.3.4.0。

**证据 3：全库字节搜索**，`1.2.6.0` / `1.3.0.0` 除本节与 `INDEX.md` 自己列出的名字外**零命中**（这条只覆盖仓库，是上面漏掉装机目录的原因）。

**证据 4：装机备份 DLL 的内嵌版本串**（`C:\Program Files\Common Files\OFX\...\Win64\DaVinciBeauty.ofx.bak-<版本>`）
逐个读二进制里的 `1.x.y.z` 字符串，与自己文件名比对：`1.2.6.0`、`1.2.7.0`、`1.2.8.0`、`1.2.9.0`、`1.3.1.0`、`1.3.4.0` 都命中自身；`1.2.4.0`→`1.2.3.0`、`1.3.2.0`→`1.3.1.0`、`1.3.3.0`→`1.3.1.0` 不命中。这组对照既证明 `1.2.6.0` 存在过，也证明 `1.3.2/1.3.3` 只是标签。

两次都只改 `gpu_smooth.cpp` 与性能文档，没动版本宏、没出包，属诊断实验。结论已并入 1.3.4.0 那一条，此处只留索引：
