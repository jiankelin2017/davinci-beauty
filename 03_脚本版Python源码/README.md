## 二、怎么用

1. 打开项目，选中一条时间线（上面要有视频片段）
2. 走上面的菜单入口
3. 选「处理目标」：`全部 N 条` = 每条都处理；`<1> xxx.mp4` = 只处理某一条
4. **调参数时点「预览当前帧」看效果**（见下节），不用等整段跑完
5. 拖滑块调强度，选磨皮算法和输出编码
6. 点「开始处理」
7. 成品自动导入媒体池，**手动拖到时间线上替换原片段**

成品文件名 = `原名_beauty.mp4`，跟源素材同目录。

## 二之二、预览当前帧（调参必备）

把播放头停在想看的画面上 → 点 **「预览当前帧」**，约 3 秒后会弹出一张
**左右并排的对比大图**：

```
┌────────────┬────────────┐
│  源素材原帧  │  美颜处理后  │      ← 中间一条白色分隔线
└────────────┴────────────┘
```

- 预览取的是**播放头所在片段、播放头所在的那一帧**（自动换算成源素材内的秒数）。
- 播放头不在任何视频片段上时，自动退回该片段的中间帧。
- 图存到 `C:\ProgramData\NamaBeauty\logs\preview_compare.jpg`，每次覆盖。
- 用系统看图器打开。**刻意用大图而不是嵌在窗口里**——磨皮和亮眼这类效果
  在缩略图尺寸下根本看不出来。
- 想再看一次，点「打开上次预览」，不会重新计算。

**注意：预览基于源素材原始帧，不含时间线上的调色。**
这是刻意和成片流程对齐的——成片是「源素材 → 美颜 → 回 Resolve 调色」，
所以预览看到的正是会被美颜的那一帧原貌。如果你已在时间线上调过色，
预览会比你时间线上看到的更「素」，这是正常的。

预览走的是独立的一套文件（`job_preview.json` / `progress_preview.txt` /
`result_preview.json`），不会和处理任务互相覆盖。

## 二之三、实时预览（拖动滑块即所见即所得）

点 **「实时预览：开」**，会另外弹出一个常驻窗口，左边原始画面、右边美颜效果。
之后**拖动任意滑块，画面立刻跟着变**，不用再一帧一帧地点预览。

```
┌──────────────────────────────────────────┐
│ 实时预览中  渲染 12.0 ms  贴图 25.0 ms     │
├────────────────────┬─────────────────────┤
│      原始画面       │      美颜效果        │
├────────────────────┴─────────────────────┤
│ xxx.mp4  位置 5.00s  输出 720x1280  刷新 12 次│
└──────────────────────────────────────────┘
```

### 为什么单帧预览要 3 秒，实时却能跟手

把单帧预览拆开看，真正干活的部分只占一小截：

| 环节 | 耗时 |
|---|---|
| fuSetup + 人脸模型 + 美颜道具 | **1842 ms** ← 每次都要重来一遍 |
| 抽一帧（ffmpeg 冷启动） | 250 ms |
| 渲染 | 5 ms |
| 编码成 JPEG（再起一个 ffmpeg） | 154 ms |

所以实时预览换了个做法：**进程常驻**。`nama_live.py` 只启动一次，把
GL 上下文、SDK、模型全留在内存里，之后每帧只剩「渲染 + 贴图」：

| 环节 | 耗时 |
|---|---|
| 渲染 | 12 ms |
| 贴图（PPM → Tk） | 25 ms |
| **合计** | **约 39 ms → 26 fps** |

换帧（把播放头挪到别处）要重新解码，约多花 0.25 秒，这是常态、
不是卡顿。

### 怎么用

1. 点 **「实时预览：开」** —— 首次约 2 秒加载引擎，窗口随即出现。
2. 拖动滑块、切换磨皮算法、勾选「只磨皮肤区域」，画面即时刷新。
3. 把播放头挪到别的时间点，窗口会跟着换成那一帧。
4. 再点一次按钮（或直接关掉美颜面板）即关闭，常驻进程会自行退出。

### 几个说明

- 预览基于**源素材原始帧**，不含时间线调色，和「预览当前帧」的口径一致。
- 窗口分辨率自动适配屏幕：单边最多 820 px，也会按源素材比例缩放。
  想要更大更清楚，用「预览当前帧」出全尺寸对比图。
- 面板与常驻进程靠 `live\live.json` 通信、靠 `live\live.hb` 心跳。
  面板关掉后进程最多 20 秒自行退出，不会留孤儿；正常关闭是立即退出的。
- 如果窗口一直不出现，看 `logs\live.log`。

## 三、8 个效果（刻度 0-100）

换算方式：`SDK 值 = 刻度 ÷ 100 × SDK 上限`

| 效果 | SDK 参数 | SDK 上限 | 默认 | 实测 efficacy（本机 blur_test） |
|---|---|---|---|---|
| 磨皮 | blur_level | 6.0 | 70 | 平均差异 2.579，改动像素 26.36% |
| 清晰 | clarity | 1.0 | 0 | 平均差异 6.536，改动像素 89.29% |
| 美白 | color_level | 2.0 | 15 | 平均差异 21.586，改动像素 99.37% |
| 红润 | red_level | 1.0 | 30 | 平均差异 3.625，改动像素 57.78% |
| 锐化 | sharpen | 1.0 | 0 | 平均差异 1.898，改动像素 8.17% |
| 五官立体 | face_threed | 1.0 | 0 | 平均差异 1.474，改动像素 15.61% |
| 亮眼 | eye_bright | 1.0 | 0 | 平均差异 0.086，改动像素 0.65% |
| 去黑眼圈 | remove_pouch_strength | 1.0 | 0 | 平均差异 0.075，改动像素 0.93% |

**两个实测结论，务必注意：**

1. **锐化与磨皮互斥。** 只要磨皮不为 0，锐化就被完全盖掉（实测三档磨皮下
   锐化效果均为 0.000）。要用锐化必须把磨皮调到 0。
2. **亮眼、去黑眼圈很弱。** 满量程改动像素不足 1%，正常观看基本看不出，
   要放大画面才看得到。

**磨皮算法**（blur_type，数值＝细节能量，越小越平滑；不磨皮为 4.184）：

| 选项 | 取值 | 细节能量 |
|---|---|---|
| 双边滤波（最强·推荐） | 1 | 3.371 |
| 高斯（中等） | 0 | 3.617 |
| 弱磨皮 | 2 | 3.833 |

> 取值 3 实测细节能量 4.184，等于完全不磨皮，已从面板剔除。

## 四、和 Qwen ASR 的关系

架构完全一致：

```
Lua 前端（达芬奇原生窗口）  →  Python 引擎（nama_worker.py）
    fusion.UIManager
      → bmd.UIDispatcher
      → dispatcher:AddWindow + On.Timeout + RunLoop
```

**前端为什么用 Lua 而不是 Python：**
Resolve 通用脚本目录下的 Python 环境**没有 bmd 模块**（本机实测
`No module named 'bmd'`），而 Lua 环境下 **bmd 是内置的**。
想要达芬奇原生窗口，只能走 Lua。

### 实时预览为什么用 PPM 而不是 PNG

同一张 1444×1280 的对比图，三条路径实测（`tests\probe_tk3.py`）：

| 路径 | 编码 | 贴到窗口 | 合计 |
|---|---|---|---|
| PNG（base64 传给 Tk） | 69.4 ms | 68.2 ms | 137.5 ms |
| PNG（落盘再读） | 65.4 ms | 52.5 ms | 117.9 ms |
| **PPM（落盘再读）** | **4.6 ms** | **21.6 ms** | **26.1 ms** |

PNG 要 zlib 压真实照片，这是实打实的 CPU 时间；而且 Tk 的 `-data` 通道
只收 base64 字符串，又多一道编解码。PPM 无压缩、Tk 原生支持，还能直接
用 `ndarray.tofile` 写进已打开的文件句柄，一次拷贝都不做。

另有 OFX 实时滤镜版装在
`C:\Program Files\Common Files\OFX\Plugins\NamaBeauty.ofx.bundle`。

## 六、故障排查

| 症状 | 原因 / 处理 |
|---|---|
| 菜单里没有入口 | 重启 Resolve；确认脚本在 `Fusion\Scripts\Utility\` 下（不是 `Support\Scripts\`） |
| 窗口一闪而过 | 看 Console 日志 |
| 「取不到 Resolve 对象」 | 必须走 工作区→脚本 菜单，不能外部 Python 跑 |
| 「没有带磁盘源文件的视频片段」 | 生成器、复合片段没有源文件，处理不了 |
| 一直停在「处理中…」 | 看 logs\progress.txt 是否在动；20 分钟无结果自动放弃 |
| 处理失败 | 看 logs\ 下的渲染日志，多为素材编码或显卡驱动问题 |
| 预览一直不出图 | 看 logs\result_preview.json 是否生成；3 分钟无结果自动放弃 |
| 预览失败：抽帧失败 | 播放头位置超出源素材时长，把播放头往前挪一点再试 |
| 实时预览窗口不出现 | 看 `logs\live.log`；引擎首次加载要 2 秒，先等一等 |
| 实时预览窗口自己消失了 | 面板的心跳断了（定时器没跑起来）。关掉面板重开即可 |
| 实时预览不动了 | 确认面板上按钮是「实时预览：开」；心跳文件 `live\live.hb` 是否在更新 |
| 残留 fuscript 进程 | 关面板时会自动清；异常情况下手动结束，或删掉 `live\live.quit` 让它自己退 |
| 选了 ProRes 后处理报错 | **已知问题**：输出文件名被写死成 `.mp4`，而 mp4 容器装不下 ProRes，必然失败。暂时请用 H.264 两种预设 |

**看日志：工作区 → 控制台 (Console) → 切到 Show All。**
进度另有一份：`C:\ProgramData\NamaBeauty\logs\progress.txt`。
